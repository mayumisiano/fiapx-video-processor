# 0004. MinIO for file storage, presigned URLs for download

Status: accepted

## Context

Videos and result `.zip` files need somewhere to live outside the containers, and clients need a way to download the result without the flow being tied to one machine's local disk.

## Decision

Store both original videos and result `.zip` files in MinIO (S3-compatible). Downloads are served via a presigned URL generated by `api`; the binary itself never flows through `api`.

Because the API's internal network address (e.g. `minio:9000` inside Docker) isn't reachable from a browser, presigning uses a second MinIO client instance pointed at a publicly reachable endpoint, sharing the same credentials.

## Consequences

- Multiple `worker` replicas need no shared-file coordination — any replica can read/write any object.
- `api` doesn't spend memory or bandwidth streaming result files; it only issues a signed URL.
- Bucket lifecycle policies can expire old files automatically, no custom cleanup job needed.
- Cost: two MinIO client instances to keep in sync (internal vs. public endpoint) whenever network topology changes — documented in `internal/videoprocessing/storage/minio.go`, easy to forget if the deployment topology changes later.
